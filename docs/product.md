# JEVia 产品介绍

JEVia 是一个本地运行的通用 agent。它把一件事拆成两半：**能用判断解决的，交给 Jev；必须写出来的，才交给语言模型**。

Jev 是 TypeSafe 的 System One 模型。你给它一段材料和几个有类型的问题，它返回带校准概率的答案——分类、评分、是否。它不写字，几百毫秒返回，每百万输入 token 约 0.042 美元。语言模型写散文和代码，贵得多。

大部分真实任务里，"判断"穿着"写作"的外衣：这封投诉要不要回、属于哪一类、有多急、该由谁处理、该写多少。以前这些全都由一个昂贵的模型在输出 token 里完成。JEVia 把它们分开。

---

## 一、它能做什么

### 跑一个任务

你说一句话，它自己决定怎么办：要不要联网查、是不是要分几步、该用哪个模型、需不需要做成一个能点的页面。这些决定全部由 Jev 在一次批量调用里完成，不是关键词匹配。

### 工具循环

写作模型可以调用工具、看到结果、再决定下一步：读文件 → 发现线索 → 读另一个 → 改一处 → 跑一下验证 → 作答。

- 一个 **step** 是一次模型请求加它调用的工具
- 一个 **turn** 持续到不再欠任何工作（模型不再要工具，或预算用完）
- 不提供工具时，循环退化成一次请求

工具按权限档位开放：

| 档位 | 能做什么 |
| --- | --- |
| 只读 | 读文件、列目录、全文搜索、抓网页、联网搜索、算术、清单、提问、委派 |
| 读写（默认） | 以上，加上写文件和**精确替换**（`old_text` 在文件里不唯一就拒绝执行） |
| 还能执行 | 以上，加上 shell、运行 Python、后台任务。需要显式设置 `JEVIA_ENABLE_SHELL=1` |

其中两个值得单独说：

- **提问**：任务模糊时它真的会停下来问你，并等你回答，而不是赌一把。并行的几个工人可以各挂一个问题。
- **委派**：把一件自足的活交给另一个模型，只拿回结论。一次冗长的翻找留在别处，不会塞满主上下文。

### 联网研究

问一件材料里没有的事，它会去查。流程是：

```
搜索  ──►  10 条结果   ──►  1 次 Jev 调用  ──►  打开 3 条
抓取  ──►  26 个段落   ──►  1 次 Jev 调用  ──►  保留 17，待复核 2，排除 7
检查  ──►  实际要交给写作模型的那部分  ──►  1 次 Jev 调用  ──►  充分（P(yes) 0.92 ≥ 0.70）
```

每段材料的去留由 Jev 一次判完，不是让贵模型把十条摘要读一遍。**充分性检查针对的是写作模型真正会收到的那份证据**，不是筛选前的原始材料——这两者不是一回事，混淆会让"资料够了"这个结论失去意义。

没有答案、请求失败、缺少字段，一律算"未知"，不算"够了"。停止原因分为：充分、轮数用完、没有新来源、出错、已取消。

### 做成一个能用的页面

要的是工具而不是文章时，Jev 从 14 个组件里挑出需要的几个并决定版式，便宜的模型只负责填词，程序负责渲染。需要自定义逻辑的（小游戏、计算器）则整页写出来。页面在沙箱 iframe 里运行，并且带内容安全策略——拿不到主页面、存储和密钥，也不能对外发请求。

### 判断可见

每个回答顶部有一张运行卡片：当前阶段、谁在工作（Jev / 策略 / 语言模型 / 工具）、真实耗时。点开右侧的 Decisions 视图能看到全过程：

- **每个批次**：8 个问题就是 1 次调用、8 个答案，等待时是中性占位，返回后一起落定。失败就是失败，不会变成一个红色的"否"。
- **三种题型各按本来面目显示**：是否题给 `P(yes)` 和阈值方向；选择题的选中概率和置信度分开显示，其余概率质量一键可见且不会被重新归一化；评分题按它自己的量表画，原始小数和策略采用的整数分列。
- **材料分组**：保留 / 待复核 / 排除 / 未判断，数字加得起来。"排除"意味着没交给写作模型，不代表删除了任何东西。
- **分流**：Jev 给的原始评分和策略最终选的模型分两边显示，中间一条连接线。没达标的候选写明"低于所需档位"。
- **没有发生的事**：只有确实由判断完成交付时才显示"跳过生成"；只有整次运行一次模型都没调时才显示"0 次调用"。

### 技能

一个 markdown 文件描述一类工作该怎么做好。内置 8 个，你可以写、可以从链接安装、也可以直接上传 `.md` 或一整包 `.zip`。用哪个技能是一道有类型的选择题，**在本来就要发的那次调用里顺便问掉**——不额外花钱。低于 50% 置信度就不套用任何技能。

### 工人

多步骤任务会拆成几个工人，各自跑在够用的最便宜模型上，互不依赖时并行。每个工人可以单独对话："这段改短一点"——它只重写自己那部分。直接拼接的整体会原地替换；被整体重写过的稿子会标记"待同步"，点一下只重跑组装那一步。

### 循环与定时

给一个目标就变成循环：字数上限、必须包含某词这类条件**由代码检查并写明计数规范**，其余交给 Jev。所有条件都满足才叫"达成目标"，跑满轮数叫"达到上限"，两者分开显示。

### 外部工具（MCP）

支持 [MCP](https://modelcontextprotocol.io) 客户端，别人写好的工具可以直接接进来。服务器只能在 `<工作区>/.jevia/mcp.json` 配置，模型无法自己添加；它的工具走和内置工具同一个安全网关。

### 其他

- **自带密钥**，支持多个服务商；模型清单和价格从服务商拉取
- **双语界面**：固定界面词跟随界面语言，内容保持原语言
- **产物落在你的文件夹里**：对话是 markdown，每步产出、证据、应用都是独立文件，不依赖本程序也能读
- **离线演示**：6 组 fixture 可以在不调用任何模型的情况下回放完整流程

## 二、技术架构

零第三方依赖，Python 3.9 标准库 + 原生 JS。后端是 `ThreadingHTTPServer` + SSE，前端是 ES 模块，没有构建步骤。

### 模块

| 文件 | 职责 |
| --- | --- |
| `questions.py` | Jev 的三种题型与答案，本地校验 |
| `roster.py` | 你的模型与密钥，以及"最便宜且达标"的选择器 |
| `planner.py` | 任务 → 计划：声明的、识别的、缓存的、编译的 |
| `agent.py` | 研究循环与步骤分流，Jev 做筛选 |
| `executor.py` | 执行一个计划：一次 Jev 调用，然后只跑活下来的部分 |
| `loop.py` | 工具循环：turn、step、安全网关、预算 |
| `session.py` | 每一步据以构建的日志 |
| `tools.py` | 工具注册表与硬规则 |
| `mcp.py` | 外部工具：stdio 上的 JSON-RPC 客户端 |
| `events.py` | 决策事件协议：按运行隔离的出口、取消、记录 |
| `policy.py` | 纯规则：什么算存疑，以及所有提示词 |
| `ledger.py` | 按 call_id 归集的费用与来源 |
| `redact.py` | 密钥、请求头、cookie 的脱敏 |
| `server.py` | 本地 HTTP、SSE 和静态界面 |

### 一次运行

```
任务
 ├─ 评估      一次 Jev 调用：要联网吗？要分几步？要做成应用吗？用哪个技能？
 ├─ 规划      声明 / 识别 / 缓存 / 编译，前三种不花钱
 ├─ 研究      搜索 → Jev 挑开哪些 → 抓取 → Jev 筛段落 → 程序构建交付快照
 │            → Jev 判断这份快照够不够
 ├─ 分流      一次 Jev 调用给每个步骤定档位、角色、是否要自己查、材料是否已覆盖
 ├─ 工作      每步一个 turn，跑在够用的最便宜模型上，互不依赖时并行
 │  └─ step   一次请求 + 它调用的工具 → 结果回灌 → 再一次请求，直到不欠工作
 └─ 组装      各自成篇就直接拼，Jev 说接缝会露就重写成一篇
```

### 四条关键设计

**1. 一次调用，多个判断。** N 个判断是一次往返，不是 N 次。这是整个成本结构的基础。研究每轮 3 次 Jev 调用，不管回来多少条结果。

**2. 模型看见的就是日志里写的。** `session.Log` 是只追加的记录，请求从它派生。超预算时较早的对话折成摘要，被替换的条目标记为 shadowed 而不删除，并发出事件记录压缩前后的 token 数。工具调用和它的结果永远不会被摘要拆开。

**3. 判断在前，硬规则在后。** 有副作用的调用先过 Jev 的批量判断，通过之后仍然要过工具自己的硬规则：路径必须在工作区内、禁止私有地址和云元数据地址。**概率再高也不能越界。** 可选再加一层逐次人工审批。

**4. 决策事件协议。** 每个决策时刻都是一条结构化事件：批次开始/完成/失败、证据筛选/检查、分流评估/选定/无合格模型、跳过生成、策略采用、需要复核、步骤、工具调用与结果、上下文压缩、提问与回答。

- `batch.started` 在阻塞请求返回**之前**就到达浏览器——运行在工作线程上，事件从单一队列出口发出
- 顺序号在出口统一分配，两次并行运行不会串
- 每个批次只有一个终态，迟到的事件不会把已完成的状态改回去
- payload 按事件类型白名单过滤，经过截断和脱敏
- 记录落在 `<工作区>/.jevia/runs/<run_id>.jsonl`，权限 600

### 其他值得一提的

**缓存键是保守的。** 计划缓存的键是规范化后的完整指令 + 技能内容版本 + 规划器版本 + 输入摘要。数字、否定、语序全部保留——"3 个案例"和"30 个案例"不会共用一份计划，两个方向相反的翻译也不会。

**费用口径。** 每个收费请求用一个 `call_id` 只记一次，并标明来源：服务商报告 / 价表估算 / 未知。**未知不会被当成 0**。界面不显示"省了多少"这种宣传数字，只显示实际发生的。

**故障切换在循环外面。** 模型在写出第一个字之前失败，就换下一个够档位的模型重来；已经写了一半再失败，保留已输出部分，不自动重试——读者已经看到那些字了。

**协作式取消。** 点停止后先显示"已请求取消"，执行器在发起下一次模型调用或工具步骤前检查标记。已经发给服务商的请求可能仍会计费，界面照实说明，不谎称已停止计费。

**动效不影响执行。** reducer 先提交真实状态，动画只负责表现。关闭动效后结果和调用次数完全一致。

## 三、设计思路

几条贯穿始终的原则，按重要性排列：

**能用代码判断的，不要问模型。** 字数上限是计数，不是判断题。工具参数能从用户已经写的文字里抽出来（一个路径、一个链接、一个算式），就不该花 token。模型选择是价表上的算术。

**能用一道有类型的题解决的，不要让模型写散文。** 分类、评分、是否——这些都有确定的形状，用校准概率回答比让模型用自然语言绕一圈更准也更便宜。

**判断和策略必须分开记录。** Jev 说"2.4 分"，策略说"采用 3 档"，这是两件事，界面上分两栏显示。程序按价表选出的模型，绝不标成"Jev 选了这个模型"。

**没有答案就是没有答案。** 请求失败、字段缺失、超时，全部记为"未知"，不折算成"否"，也不折算成 0。一个失败的批次显示为失败并给出原因。

**不确定就问，不要赌。** 早早赌错一次，代价是整个任务。

**拒绝要可读。** 工具被拒绝时，模型收到的是一条说明为什么以及该怎么换个做法的结果，而不是一个异常。

**不说自己省了多少。** 对照估算是模型推算，不是实测，所以从默认界面上拿掉了。

**动效呈现状态变化，不模拟思考。** 不为了好看延长执行，不给不存在的进度编百分比。

**工具权限是用户的决定，不是角色的属性。** 角色决定写作口吻，档位决定能碰什么。

## 四、安全边界

- 密钥只存在于你浏览器的 localStorage 和 `.env`（权限 600，已 gitignore）。服务器不保存，只在当次请求使用。日志只记录方法、路径、状态码。
- 事件记录、导出和错误信息全部脱敏：密钥、`Authorization`、cookie 一律不落盘。
- 默认只绑定 `127.0.0.1`。所有 POST 检查来源，跨站请求返回 403。
- 文件工具的路径解析后必须落在工作区内，符号链接也一样。
- 抓网页只允许 http/https，拒绝 localhost、内网段和云元数据地址，**每一跳重定向在跟随之前校验**。
- 生成的应用在无同源权限的 iframe 里运行，并带 `connect-src 'none'` 的内容安全策略。
- shell 和运行代码默认关闭，需要显式设置环境变量。**这不是沙箱**，开启后代码以你的身份执行。

完整清单和仍然存在的风险见 [security.md](security.md)。

## 五、不做什么

- **PTY 持久终端、LSP 跳转定义**：这是 IDE 的能力。需要的话通过 MCP 接现成的。
- **把内核做成插件树**：我们的扩展点是 MCP、技能和模型适配器，够用。
- **多智能体团队**（持久名册、任务板、信箱）：`delegate` 覆盖了"把活派出去"。在有证据表明更好之前不做。
- **动态重规划、按领域校准能力、付费对照评测**：只留了接口和记录格式（`evaluation.py`）。

## 六、怎么跑

```bash
python3 app.py                    # http://127.0.0.1:8765
python3 scripts/offline_server.py # http://127.0.0.1:8766，全假引擎，不花钱
```

第一次打开填入 API 密钥、选一个工作区就能用。

```bash
python3 -m unittest discover -s tests -t .   # 429 项，离线，不需要密钥
node scripts/ui_tests.mjs                     # 24 项，事件 reducer、动效、渲染
node scripts/copy_audit.mjs                   # 中英文案对齐
```

## 七、现状

这是一个能跑的完整产品，不是演示。但有一件事必须说清楚：**近期这些改动的验收全部在离线环境完成**——单元测试用假传输层，浏览器检查用全假引擎的服务器。线上真实延迟、真实计费字段的行为、以及各项策略阈值是否合适，都还没有在付费调用下验证过。阈值只是配置，没有经过校准，产品里也这样标注。
