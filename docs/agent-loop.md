# 工具循环 · 补齐与 dsh 的差距

这一轮把 JEVia 从"一条流水线"改成"真正的 agent"。依据是上一轮对 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的逐项对比。本文说明改了什么、怎么改的、哪些没做以及为什么。

> **仍然没有在线验证。** 所有验收都在离线完成：单元测试用假传输层，浏览器检查用 `scripts/offline_server.py`。`.env` 里的密钥没有用于任何验收调用。

## 1. 最大的一处：turn / step

以前：评估 → 规划 → 研究 → 路由 → 判断 → 生成 → 拼装。计划一次，之后不再改变，模型拿到材料必须一次性写完。

现在：**一个 step 是一次模型请求加上它调用的工具；一个 turn 持有 step，直到不再欠任何工作**（模型不再要工具，或预算用完）。

```
turn
 ├ step 1   请求（带工具 schema）→ 模型要求 read_file
 │          → 判断 → 执行 → 结果作为 tool 消息回到上下文
 ├ step 2   请求 → 模型要求 write_file → 判断 → 执行 → 结果回灌
 └ step 3   请求 → 不再要工具 → 这就是答案，turn 关闭
```

关键设计：**不提供任何工具时，循环退化成一次请求**，也就是改造之前的行为。所以整条链路只有一份代码，没有"有工具"和"没工具"两条分支。

- `jevharness/loop.py` —— `AgentLoop`、`Budget`、`Gate`、`Outcome`
- `jevharness/session.py` —— `Log`：模型看到的每一条消息都先是日志里的一条记录
- 故障切换在循环**外面**：输出前失败就换模型重来，已经输出了就保留部分结果、不重试（T17 语义不变）

## 2. 上下文：模型看见的就是日志里写的

`session.Log` 是只追加的记录，`messages()` 从它派生出请求。带来三件事：

- **压缩**：超过预算时，较早的对话交给最便宜的模型折成一段摘要，被替换的条目标记为 shadowed 而**不删除**，并发出 `context.compacted` 事件（记录压缩前后的 token 数和替换条数）。
- **工具调用与结果永远不被拆开**：摘要边界会避开"助手请求 + 工具结果"这一对。
- **system 只有一条**：设置新的会让旧的失效，模型不会同时读到两套指令。

## 3. 工具

| 新增 | 说明 |
| --- | --- |
| `edit_file` | 精确替换一段原文。要求 `old_text` 在文件中唯一，否则拒绝——改动要么落在该落的地方，要么不发生。 |
| `run_code` | 在工作区跑一小段 Python 并读取输出。需要 `JEVIA_ENABLE_SHELL=1`。 |
| `job_start` / `job_list` / `job_output` / `job_kill` | 后台跑长命令，不堵住整个回合。运行结束时一并终止。 |
| `todo_write` | 模型自己维护的清单，长任务不会悄悄少做几件。 |
| `ask_user_question` | 真的停下来问你，并等你回答。 |
| `delegate` | 把一件自足的活交给另一个模型，只拿回结论，脏上下文留在别处。 |
| `web_search` | 写作途中缺一个事实时自己去搜。 |

权限边界改了一处：以前按角色限制工具，现在**由你设的档位决定**（只读 / 读写 / 还能执行命令），角色只决定写作口吻。理由：角色是能力划分，不是权限划分；一个被要求"把草稿存下来"的写作角色应该能存。

## 4. 交互：问、批、计划

- **提问**：`RunEvents.ask()` 发出 `question.asked` 并阻塞等待。运行本来就在工作线程上，所以问题会立刻到达浏览器。没人回答会超时（默认 10 分钟），取消会释放等待。并行子任务可以各自挂一个问题，界面同时显示。
- **审批**：打开"每次改动都问我"之后，Jev 判断通过的有副作用调用还要再问你一次。顺序是先便宜的检查，再打扰人。
- **计划模式**：动手前把计划给你看。你说"改成两部分"，它带着这句话重新编译计划，再问一次（最多 3 轮）。被退回的计划不会读写缓存。

接口：`POST /api/runs` 增加 `action=answer`（同源校验、工作区校验，与取消同一条路径）。

## 5. MCP

`jevharness/mcp.py` 是一个只用标准库的 MCP 客户端：stdio 上的 JSON-RPC，`initialize` → `tools/list` → `tools/call`。

- 服务器只能配置在 `<工作区>/.jevia/mcp.json`（设置 → Tools 写入，权限 600）。模型无法添加。
- 每个远端工具变成 `<服务器名>__<工具名>`，走和内置工具同一个网关。服务器自称 `readOnlyHint` 只会降低询问强度，不会跳过判断。
- 按工作区复用已启动的服务器（配置变了才重启），运行结束不留孤儿进程。
- 测试跑的是**真的服务器进程**（`tests/fixtures/mcp_echo_server.py`），不是 mock。

## 6. 花钱方式

新增一个档位：**够用就好**（默认，每步用刚好达标的最便宜模型）与**用最强的**（凡是要写东西的步骤都用你配置里最强的模型）。Jev 的判断两档相同，变的只是从这个档位的哪一侧取模型——这一点会记录在事件里。

## 7. 没做的，以及为什么

- **PTY 持久终端**、**LSP 跳转定义**：这是 IDE 的能力。JEVia 不是 IDE，硬塞进来只会多出两个没人用的工具。需要的话，用 MCP 接现成的。
- **插件化整个内核**（dsh 的 Cordis）：它的价值在于让第三方替换任意一层。我们的扩展点是工具（MCP）、技能（markdown）和模型适配器，够用；把内核改成插件树是重写，不是优化。
- **Agent Teams**（持久名册、任务板、信箱）：`delegate` 覆盖了"把活派出去"的部分。多智能体协作在没有证据说明它更好之前不做。
