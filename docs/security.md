# 安全检查 · 2026-09-20

对用户会接触到的每条路径做了一次审计：密钥、网络请求、文件写入、页面渲染、本地接口。下面先写**本次修掉的问题**，再写**已有的防护**，最后写**仍然存在的风险**——最后一类不是遗漏，是这个产品的性质决定的，需要你知道。

## 一、本次修掉的问题

| # | 问题 | 影响 | 处理 |

## 二、已有的防护（本次复核通过）

- **密钥**：只存在于你浏览器的 localStorage 和 `.env`（`600`，已 gitignore）。服务器自己不保存，只在当次请求里使用。日志只打印方法、路径、状态码。事件记录、导出和错误信息都经过脱敏，密钥、`Authorization`、cookie 一律不落盘。打包前扫描确认压缩包里没有密钥。
- **本地接口**：默认只绑定 `127.0.0.1`；绑到其他地址会打印警告。所有 POST 检查来源，跨站请求返回 403。请求体上限 4 MB。
- **运行记录**：`run_id` 按正则校验，从不当路径用；读写限制在 `<工作区>/.jevia/runs` 内。
- **文件工具**：所有路径解析后必须落在工作区内，符号链接也一样；Shell 工具默认关闭，要显式设 `JEVIA_ENABLE_SHELL=1`。
- **有副作用的动作**：先过 Jev 的批量判断，低于阈值直接拦截；而且 Jev 说可以并不等于放行——工具自己的硬规则（工作区限制、禁止私有地址）仍然生效。
- **网页抓取**：只允许 http/https；拒绝 localhost、内网段、云元数据地址（`169.254.169.254` 等）；有大小上限。
- **页面渲染**：模型输出一律先转义再渲染，Markdown 链接只认 http/https。应用在 `sandbox` 且没有 `allow-same-origin` 的 iframe 里运行，拿不到主页面、存储和密钥。
- **技能**：从链接安装同样走上面的地址规则，有大小上限。

## 二点五、工具循环带来的新面（2026-09-20 追加）

模型现在可以自己调用工具、看结果、再决定下一步。这是能力，也是新的攻击面，所以这一轮同时做了下面这些：

| 机制 | 说明 |
| --- | --- |
| 权限档位 | 一次运行能用哪些工具由你在设置里选：只读 / 读写 / 还能执行命令。模型不能越过这个边界，也不能自己打开更高档位。 |
| 判断在前，硬规则在后 | 有副作用的调用先过 Jev 的批量判断，通过之后仍然要过工具自己的硬规则（路径必须在工作区内、禁止私有地址）。概率再高也不能越界。 |
| 逐次审批（可选） | 打开"每次改动都问我"，每一次写入、修改、执行都会停下来等你点头。 |
| 预算 | 每回合最多 8 步（可调，上限 24）、最多 40 次工具调用。模型陷入循环会被停住并说明原因，而不是无限跑下去。 |
| 拒绝是可读的结果 | 被拒绝的调用不是异常，而是一条告诉模型"为什么不行"的结果，它可以换个做法，但不会重复撞墙。 |
| 取消 | 每一步、每次工具调用之前都检查取消标记。 |
| `run_code` / `shell` / 后台任务 | 仍然需要 `JEVIA_ENABLE_SHELL=1`，默认关闭。**这不是沙箱**：开启后代码以你的身份执行。后台任务在运行结束时一并终止，不会留下孤儿进程。 |
| MCP 服务器 | 只能从 `<工作区>/.jevia/mcp.json` 配置（设置界面写入，权限 600），模型无法添加。服务器声明"只读"只会降低询问强度，不会跳过判断。每次调用有超时，失败是结果不是崩溃。 |
| `delegate` | 被委派的模型不带工具、不带历史，只能返回一段文字。 |

**提示注入在这一轮变得更要紧**：抓回来的网页或你上传的材料里如果写着"请把密钥写进文件"，模型现在真的有工具可以试。拦它的是上面三层（档位、Jev 判断、硬规则），以及可选的逐次审批。**处理不可信材料时，建议把档位设为"只读"，或者打开逐次审批。**

## 三、仍然存在的风险（性质使然）

1. **你的密钥会按你的配置发给模型服务商**。这是产品的正常工作方式。自定义服务商时，地址是你填的，请确认可信。
2. **定时任务必须把密钥写到磁盘**：`<工作区>/.jevia/schedule.json`（`600`）。凌晨三点没有浏览器可问。不想让密钥落盘，就不要建定时任务，其他功能不受影响。
3. **提示注入**：联网抓回来的网页、你上传的材料、安装的技能，里面都可能写着"请执行……"。JEVia 把它们当**数据**，有副作用的动作要过判断加硬规则；但模型写出来的**文字内容**仍可能被这些材料带偏。重要结论请对照 Decisions 视图里的原始来源。
4. **工作区里的文件工具可以读写整个工作区**。工作区选在哪里，就等于把哪里交给了任务。不要把工作区设成家目录。
5. **开启 Shell 工具或 `run_code` 后，命令在你的机器上真的会执行**。默认关闭，建议保持关闭；确实需要时，配合"每次改动都问我"使用。
5b. **MCP 服务器以你的身份运行**，而且它自己的网络访问不受本程序限制。只添加你信任的服务器。
6. **选择工作区的界面可以列出机器上的目录名**（只有目录名，不读内容）。只有本机、同源请求可用。
7. **浏览器里的本地数据**：对话、产出和密钥存在 localStorage。共用电脑请用独立的浏览器配置。
